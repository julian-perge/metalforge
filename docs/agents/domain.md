# Domain docs

This repo uses a single-context layout: root `GLOSSARY.md` and `docs/adr/`.

## Before exploring

Read [GLOSSARY.md](../../GLOSSARY.md) and any ADRs under `docs/adr/` relevant to the area being explored.

If a domain file or directory does not exist, proceed silently. Do not suggest creating it upfront. The domain-modeling skill creates documentation when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms in issue titles, proposals, hypotheses and test names. Follow its explicit guidance on synonyms to avoid.

If a needed concept is absent, reconsider whether it belongs to the project vocabulary. Record a real terminology gap for domain modeling.

## Decisions

Surface any conflict with an existing ADR explicitly rather than silently overriding the decision.
